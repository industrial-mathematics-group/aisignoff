## Findings in this change

### Minor — The v0.19.2 cache fix needs an upgrade note or cache invalidation

[`docs/changelog.md:10`](../docs/changelog.md#L10) says stale provenance for non-ASCII paths was fixed, and the updated [CI recipe](../docs/cache.md#L30) restores caches and points to v0.19.2. A repository that stored the wrong result with v0.19.1 will still report H1 after upgrading, while an uncached run reports the correct H3. The release notes give no step to recover from the previous release's stale entries.

Invalidate old cached unit origins on upgrade, or document that affected users should discard the existing cache and change the CI cache key. Disabling it with `AISIGNOFF_NO_CACHE=1` gives the correct result in the meantime.

## Outside this change

- **Major, still open in the cache finding.** v0.19.1 can store an incorrect unit origin at the current commit. The fix changes how paths are collected between commits, while the existing cache reader uses the old entry directly when it already belongs to the current commit. The cache format and key are unchanged. A warm cache rebuilt using only v0.19.2 works for the original non-ASCII case. [Cache key](../src/aisignoff/cache.py#L77), [unit lookup](../src/aisignoff/cache.py#L170)
- **Minor, still open in the cache finding.** Both versions return cached H1 and uncached H3 after editing a binary named `\nreport.bin`. v0.19.1 compares raw filenames to quoted names. v0.19.2 reads NUL-delimited names but strips actual leading newlines with `lstrip("\n")`. Consume Git's framing without stripping filename bytes. [Path parsing](../src/aisignoff/history.py#L1530)
