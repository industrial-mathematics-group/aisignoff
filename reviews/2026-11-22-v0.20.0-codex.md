## Findings in this change

### Minor — A shebang argument can override the actual interpreter

[`src/aisignoff/report.html:577`](../src/aisignoff/report.html#L577)

An extensionless file with `#!/usr/bin/env -S python3 -X pycache_prefix=/tmp/sh` is highlighted as Bash. The same file with `#!/usr/bin/env python3` is highlighted as Python. Both are Python shebangs. The greedy prefix in the regular expression makes the final supported word, `sh` in an option value, win.

Parse the interpreter command first. For `env`, account for `-S` and leading options and assignments, then match the interpreter basename. Test that later arguments cannot change the choice.

## Outside this change

### Major — Diff and history disagree about binary content around their probe boundaries

[`src/aisignoff/diff.py:102`](../src/aisignoff/diff.py#L102), [`src/aisignoff/diff.py:207`](../src/aisignoff/diff.py#L207), [history consumer](../src/aisignoff/history.py#L1567)

Both cases reproduce on v0.19.3 and v0.20.0. The affected diff logic predates the release's new syntax feature.

- **NUL at byte offset 10,000.** The old file has a NUL in its first line and two ordinary lines after it. A branch replaces the first line with text and retains the other two strings. By aisignoff's 16 KiB probe, the old file is one binary unit. Git emits a text hunk with one addition and one removal. The PR report gives line 1 the new H3 and assigns the old binary commit's H1 to lines 2–3. All three new text lines should take the change's declaration because the old file was represented as one unit.
- **NUL at byte offset 18,000 after 9,000 UTF-8 characters.** With `-diff` set, the old file is text by aisignoff's byte rule. The parser decodes the blob and checks the first 16,384 characters, so it treats the old text as binary. A one-line edit then gives all three lines the new H3 and reports three additions and one removal. The unchanged lines should keep H1, and the counts should be one and one.

Use a shared byte-based probe on both sides before building line maps. Apply it even when Git reports a text hunk. Keep Git's patches for pairs that are text under the shared rule.
