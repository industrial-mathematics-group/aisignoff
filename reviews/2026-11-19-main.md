## Findings

### Major — `diff` omits new reviews for an already attested file

At the reviewed tip, `src/aisignoff/diff.py:237` and `src/aisignoff/diff.py:286` identify attestations by path and blob alone. Attest a file at H3 and commit the record. Then attest the unchanged file at A2 and run `aisignoff diff BASE --json` against that commit. The `attested` array is empty even though the change added an AI review. This hides the entire review event in the diff report for an ordinary workflow where human and AI reviews arrive separately.

This predates PR #37, whose diff leaves the attestation comparison untouched. It affects the broader tool audit and leaves the three attested modules unaffected. Commit `de3496361096c16c9d0f259b1486cc9a3ca7a6f7` fixes it by comparing the path, blob, and declaration together while accounting for repeated entries. The CLI regression test fails on the reviewed source and passes with the fix. The fix awaits a fresh independent review.

### Trivial — `init` documentation describes an absent commented block

At `docs/commands.md:57`, the text says both configuration blocks stay commented out when the options are omitted. A plain `aisignoff init` writes a commented `[review]` example and omits `[history]` entirely. The behavior is covered by the configuration default. The documentation could say it omits `[history]` unless `--history` is given. Open.
