## Findings in this change

### Minor — Git encoding filters make an unchanged unit count differently on either side of the diff

[`src/aisignoff/diff.py:271`](../src/aisignoff/diff.py#L271), [replacement count](../src/aisignoff/diff.py#L280)

Set `notes.txt working-tree-encoding=UTF-16LE` in `.gitattributes`, commit a three-line file, and edit its first line on a branch. Both checkouts use UTF-16LE, so aisignoff's working-tree rule counts each file as one unit. v0.20.1 shows one added unit and three removed units, all three removals attributed to the base's H1 declaration. v0.20.0 and the ordinary UTF-8 control show one added and one removed unit.

The old side is classified from the canonical UTF-8 Git blob, while the new side is classified from actual UTF-16LE bytes. Aisignoff sees a text-to-binary boundary where both checkouts have the same encoding. It then applies the base declaration three times to the old file's single unit.

Compare the two sides in a consistent representation. If reports count the checked-out bytes, classify the old side using the base revision's checkout encoding as well. Add a test with the same Git encoding attribute on both revisions.
