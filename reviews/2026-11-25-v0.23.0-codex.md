## Findings in this change

### Minor — Editing a multiline symlink target can count more than one unit removed

[`src/aisignoff/diff.py:207`](../src/aisignoff/diff.py#L207), [`src/aisignoff/diff.py:445`](../src/aisignoff/diff.py#L445)

Change a symlink target from `first\nold\nsecond` to `other\nsecond\nthird`. Both versions of the link count as a single unit under the history rules. v0.23.0 reports two additions and two removals. v0.22.0 already overcounted additions, but reported one removal. The previous collector capped removed hunk lines to the old file's known units. The new normalization applies only to NUL-classified old blobs, so it misses mode `120000` (symlink). This affects counts for valid link targets containing newlines.

Carry the old and new Git modes into the unit-counting path. Count a changed symlink as one unit on each side where it exists. Preserve the prior ownership of a link that is only renamed.

## Outside this change

- **Minor — A binary version can disappear with zero removals.** Insert a 17,000-byte line before a file containing a NUL at byte zero. The old version is binary and the new version is text by the probe rule. Git reports an insertion and no removals. Both releases report `+1 -0` because the binary-old normalization only acts when a hunk has removed lines. The old binary unit was replaced, so the documented diff should count one removal while preserving the textual ownership Git gives the surviving lines. [Unit normalization](../src/aisignoff/diff.py#L212), [documented rule](../docs/history.md#special-cases)
- **Minor — A PR that removes a legacy unknown key still fails the base-config check.** The v0.22.0 review reported this case. Plain lint passes on the cleanup branch, but lint with `--base main --declare-from` exits 2 in both releases. Base-rule loading still parses the old file with the same strict parser. Document how to remove the legacy key before switching the workflow pin, or provide a targeted cleanup path that still enforces the base rules. [Base rules](../src/aisignoff/pullrequest.py#L117)
