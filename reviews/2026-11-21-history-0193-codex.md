## Findings in this change

### Major — Git's suppressed text patch is treated as a full rewrite

[`src/aisignoff/diff.py:177`](../src/aisignoff/diff.py#L177), [history consumer](../src/aisignoff/history.py#L1567)

Set `data.txt -diff` in `.gitattributes` and change only line 1 of a three-line text file on a pull request branch. With an H1 base and an H3 pull request declaration, v0.19.3 reports every line as H3 and counts three additions and three deletions. The control with ordinary text diff reports H3 on line 1, retains H1 on lines 2–3, and counts one addition and one deletion. v0.19.2 also reports those correct results for this fixture with `-diff`.

Git emits the same `Binary files … differ` header when an attribute suppresses a text patch. The new branch counts the lines on both sides and passes all of them to history as replacements. That discards valid provenance for unchanged content.

Determine both sides' content classification using the same rules as history. If both sides are text and the patch was suppressed, recover their actual line changes with a text diff using the project's whitespace setting. Keep full replacement semantics when one side is binary.
